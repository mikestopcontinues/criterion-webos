# Official Reference App

Behavioral acceptance requires a running current Criterion TV app, as specified by [the product contract](product.md). Publisher screenshots establish visible design, and help articles establish documented behavior; neither proves the app's actual focus, player, account or synchronization behavior.

## Reference access and identity

The selected local route is a host-native Google TV emulator on the captain's Apple Silicon Mac. Google's SDK supplies an Android 14/API 34 ARM64 Google TV image whose installed `advancedFeatures.ini` enables `PlayStoreImage`. The isolated `CriterionReferenceTV` AVD uses Google's 1080p television profile. The native emulator's Hypervisor.Framework check passes. Root verified API 34 boot completion through ADB, the installed Play Store package, software rendering and disabled audio. Google explicitly excludes Docker and other nested VMs from its accelerated-emulator route. Root owns the serialized emulator, browser and account queue. A running official Criterion app remains unestablished. See [Google's virtual TV setup](https://developer.android.com/training/tv/get-started/create) and [emulator acceleration requirements](https://developer.android.com/studio/run/emulator-acceleration).

The current unified [Google Play listing](https://play.google.com/store/apps/details?id=com.criterionchannel&hl=en_US&gl=US) identifies `com.criterionchannel` version `11.0.18`. Exact TV variant selection matters: the available version `11.0.18` artifact with version code `11101800` has only the ordinary mobile launcher and is unsuitable for TV comparison. An [Android TV mirror candidate](https://www.apkmirror.com/apk/the-criterion-collection/the-criterion-channel-android-tv/the-criterion-channel-android-tv-11-0-18-release/the-criterion-channel-android-tv-11-0-18-3-android-apk-download/) reports code `11001800`, Android 10+, ARM64 and 320 dpi in a split bundle. Its actual bytes and TV manifest remain unverified; a mirror description is insufficient for admission.

Criterion publishes an authoritative Android signing identity at [its first-party asset-links endpoint](https://www.criterionchannel.com/.well-known/assetlinks.json). The production package permits the SHA-256 fingerprint `71:2B:2F:12:9B:29:F4:87:F5:59:51:3F:38:44:48:64:E9:08:5F:81:4F:D5:9B:88:8A:68:31:90:05:F7:95:2D`, among other listed fingerprints. Admission of a publicly obtained reference bundle requires Google's `apksigner` to verify every installed APK against the current first-party package identity, matching package/version across splits, a real TV launcher manifest and a recorded bundle hash. Keep binaries, private evidence and subsequent account data outside Git; do not redistribute the reference app. Matching a signer does not prove that a mobile artifact implements the TV interface.

No anonymous first-party APK delivery endpoint is established. Official acquisition uses the Play Store and a Google account. The public mirror route remains a candidate until a successful download and verification. The [Criterion FAQ](https://www.criterion.com/faq/channel) explicitly permits app catalog browsing without an active subscription; playback, My List and progress acceptance still require the captain's subscriber access.

Apple's current [US app listing](https://apps.apple.com/us/app/the-criterion-channel/id1454275199?platform=mac) excludes iOS installation on Apple Silicon Macs: its public metadata sets `isIOSBinaryMacOSCompatible` and `hasMacIPAPackage` to false. The [current Apple lookup](https://itunes.apple.com/lookup?id=1454275199&country=us) identifies version `11.0.3`. A production tvOS App Store binary is also distinct from a simulator build. See [Apple's Mac availability rules](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/manage-availability-of-iphone-and-ipad-apps-on-macs-with-apple-silicon).

## Comparison procedure

Install only an admitted TV package or the exact official Store-delivered package. Record its installed version, source hash and signing identity before comparison. Exercise public browsing first, then authorized subscriber behavior. Capture original app frames and remote inputs; associate each claim with its actual platform and app version. Keep screenshots, native evidence, subscriber outcomes, physical controller feel and audible output as distinct evidence layers. The primary shared log records acquisition and verification history; [TASKS.md](../TASKS.md) owns unfinished acceptance.
