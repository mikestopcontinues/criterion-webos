# Criterion Provider Contract

Public browsing works through Criterion Channel's current first-party JSON routes and parsed discovery pages. These are observed, undocumented service contracts; they establish technical behavior, not a supported third-party API or provider permission. [Subscriber session admission](session.md) establishes host device linking and logout; [the account boundary](account.md) admits the initial native Watch List read in the composed host application. Other subscriber methods, account synchronization and licensed C4 playback remain unverified. [Product acceptance](product.md) owns those admission requirements.

## Public catalog

Use HTTPS at `www.criterionchannel.com`. The following public GET routes returned JSON without cookies or authorization. [Fixture provenance](../tests/fixtures/provider/provenance.json) records exact requests, capture times and hashes; the [fixture index](../tests/fixtures/provider/README.md) describes the bounded extracts.

| Route | Response and parameters |
| --- | --- |
| `/api/all-films/results` | `{ items, total, paging }`; `page_limit` and optional `pagination_key`. `paging.next_pagination_key` is an opaque continuation token; absence ends pagination. No previous-page token was observed. |
| `/api/all-films/filters` | `{ sortOptions: [{ label, value }], filterGroups: [{ label, value, options: [{ label, value }] }] }`. |
| `/api/search?q=<encoded query>` | `{ playlist, type_counts, paging }`. The web client requests one result set and filters its content types locally; no search continuation request is established. |
| `/api/media/<media ID>` | A single detailed media object, including optional nested `playlists`. The web helper accepts `fresh=1` for a fresh request. |

All-films filter parameters are `genres`, `decades`, `countries` and `directors`, containing comma-separated option values. Treat option values as bounded provider identifiers and preserve their case/Unicode; observed values include `González-juan-pablo` and `Hung-sammo`. Encode values through the URL query builder instead of concatenating raw strings. Sorting uses `sort=title|director|year|primary_country_slug|duration` and `sortDir=asc|desc`; defaults are title ascending. The web client requests 60 items per page. A live request combining `genres=horror`, duration sorting and descending direction returned films in descending duration order. Search trims the query and waits 250 milliseconds after changes. These client rules come from the [all-films bundle](https://www.criterionchannel.com/_next/static/chunks/06e9ymw11xjmc.js) and [search bundle](https://www.criterionchannel.com/_next/static/chunks/04xx7_qje3b36.js).

Catalog IDs are exactly eight ASCII alphanumeric characters in the current [media helper](https://www.criterionchannel.com/_next/static/chunks/3-c73_d_zowt2.js). Observed minimal film-list items contain `mediaid`, `title`, `contentType`, `duration` in seconds and `release_date`. Captured collection/category items omit release dates and use duration zero; no missing-duration response was observed. Client rendering tolerates missing runtime metadata, which is a source-derived tolerance rather than a demonstrated provider omission. Search and nested lists can additionally supply `criterion_id`, `feedid`, title variants, `paywall`, `drm`, commentary labels, license window timestamps, `collection_count`, `logo`, `teaser` and `deeplink`. Bound required metadata, strings, arrays, nesting and payload size; optional detail fields are not list requirements.

The live all-films response includes the optional release-date spelling `0-01-01`. The [website year helper](https://www.criterionchannel.com/_next/static/chunks/3-c73_d_zowt2.js) returns a label only for four leading digits, so this value has no year label; it does not define a general calendar or unknown-date convention. The catalog adapter maps this exact value and empty release dates to absent metadata, preserving the rest of the item and page. Other nonempty release dates must remain valid four-digit calendar dates. This exception applies only to optional media metadata; schedule timestamps still require canonical calendar-valid UTC values.

Public Search also returns `original` installments. The current [navigation helper](https://www.criterionchannel.com/_next/static/chunks/2cvc7wqvx4ird.js) maps them to `/originals/<ID>/<slug>` and labels them Installment; they are outside its category/collection/franchise compilation set. The [detail renderer](https://www.criterionchannel.com/_next/static/chunks/2tpknm2s8cqz7.js) uses single-item year/runtime metadata for film, original and episode. Keep Original as a distinct media kind, admit its matching route and render it with the existing single-item detail layout. It belongs in All search results; the Films, Collections and Supplements groups retain their exact types. The decoder admits seven known count kinds, including Original; an unknown item or count kind still rejects the response.

Detail metadata includes `director`, `starring`, `country` and `language` string arrays; description variants; genre and content warnings; trailer/introduction IDs; commentary labels; and `playlists`. Generic playlists use `{ key, title, type: "GENERIC_PLAYLIST", playlistId, playlist: [...] }`. Observed keys include `playlist_primary`, `playlist_supplements`, `playlist_collections_appears_in` and `playlist_categories_appears_in`. The current client also recognizes season playlists with `type: "seasons"` and nested season `episodes`, but no season response has been admitted as a fixture. [Detail rendering](https://www.criterionchannel.com/_next/static/chunks/2tpknm2s8cqz7.js) owns those client expectations.

The description helper considers medium/long variants: details prefer long then medium, cards medium then long; staff descriptions can override separately. Rendering treats these as text with newline breaks. The inspected responses contain plain text; arbitrary provider text must remain escaped, bounded text rather than executable HTML.

Paywall values consumed by the client are `registered`, `subscriber` and `all`. A catalog `drm` flag or license window is metadata, not permission to play. Availability depends on the current entitled response and location; cached page and API metadata can disagree. Public detail responses can contain `sources`, `tracks` and legacy `vimeo_id`; the catalog adapter must ignore them. They do not establish the current subscriber playback contract.

The web image helper constructs `https://cdn.jwplayer.com/v2/media/<ID>/images/<label>.webp?width=<positive integer>`, defaulting to `default_16x9`; some rails use `regalia_16x9`. The verified landscape route redirects to `https://img.jwplayer.com/v1/media/<ID>/images/default_16x9.webp?width=480`. The first-party [homepage](https://www.criterionchannel.com/) also configures the Fresh from Theaters rail with `imageJWLabel: default_2x3` and `imageAspectRatio: 150`. Its portrait URL family is `https://img.jwplayer.com/v1/media/<ID>/images/default_2x3.webp?width=480`; a direct HEAD for its displayed item returned image/WebP without fallback. This establishes a portrait asset family, not universal availability or the official TV app's exact label selection. Generate bounded URLs from validated IDs and fixed labels/hosts; treat absent portrait artwork explicitly rather than substituting landscape content as portrait proof. Public artwork remains provider content, not project-owned distribution artwork.

## Public discovery

Ordinary anonymous `GET /` and `GET /new` return HTML containing the curated discovery data; no cookies, RSC headers or JavaScript execution are needed. The current [Home page](https://www.criterionchannel.com/) and [New page](https://www.criterionchannel.com/new) supply ordered `{ blocks: [...] }` props to `LanderStoryBlocks`. No dedicated curated JSON API was found in their directly referenced public bundles. This is an undocumented, build-dependent HTML contract. [Discovery fixtures](../tests/fixtures/provider/README.md) preserve bounded metadata and the transport shape; provenance records exact raw response and extracted-props hashes.

Supplied internal `/discover/<slug>` destinations use the same component/data transport. The Rust TLS adapter admits the observed Newly Added, International Cinema and Shorts pages through typed, bounded `Slug` values. Their complete supplied rows expose no continuation token; all-films pagination remains a separate contract.

Extract script text as data. The observed inline statements are `self.__next_f.push([1, "<string>"])`; JSON-decode their array literals and concatenate the type-1 strings in document order. They form Next Flight records. JSON import records name `LanderStoryBlocks`; match that import reference to the React element's fourth-slot props and require one valid `blocks` array. Record IDs such as `1a`, import IDs and numeric module IDs are build-local, not stable selectors. Other records include non-JSON content and cannot all be parsed as JSON. Bound HTML, accumulated strings, record lengths, nesting and collection counts; never evaluate scripts or import downloaded modules. A missing/ambiguous component, malformed payload, geo-block page or changed transport is an explicit unavailable-contract error.

The [current block renderer](https://www.criterionchannel.com/_next/static/chunks/1efi2w06g0no5.js) consumes four block types:

| Type | Supplied data and meaning |
| --- | --- |
| `20` | A catalog rail/grid: `id`, optional `header`/`cta`/`link`, `playlistType`, optional `playlistID`, `playlist`, `imageJWLabel`, `imageAspectRatio`, `galleryPageNum`, `galleryWrap` and `variant`. |
| `21` | Navigation items: `nav: [{ id, cta, link, linkTarget, thumbs? }]`, optional `navImagePath`, and rail/grid presentation fields. |
| `22` | Editorial banner: `imagePath`, `thumbs`, optional `thumbsMobile`, `imageAlt`, `link`/`linkTarget`; `subscriptionPromo === 1` hides it when subscribed. |

For `playlistType: "playlist"`, `playlist` is the complete supplied row. Preserve array order and do not sort it locally. `galleryPageNum` is passed as cards per view, not request page size; `galleryWrap === 1` selects a grid and `0` a rail. These curated rows expose no continuation request or next token. Only `watchlist`/`continueWatching` blocks load their authenticated hooks; the renderer hides them unless subscribed and hides empty results. Anonymous captures establish placeholders, not subscriber lists or ordering. Unknown block types are skipped by the current web renderer, but missing required metadata must not be replaced with invented content.

Home's leading blocks are an editorial slideshow, Popular Movies, Leaving October 31 and Featured Collections. New's leading blocks are a film slideshow, October Collections and Newly Added Films. Exact remaining order, IDs, title facts and artwork labels belong to the captured fixtures; editorial programming and cardinalities change. The web client passes `regalia_16x9` for its film rails, `default_16x9` for collection rails, and supplied portrait/edition labels where configured. A row's `playlistID` is a feed identifier, distinct from the media ID in its See More target.

Slides, banners and navigation use their explicit `link`; `linkTarget === 1` opens a new tab on the web. Catalog cards use the validated content type, media ID and title slug through the existing media helper. Admit known internal media/discovery targets, with exact host/path bounds, rather than navigating arbitrary payload URLs or assuming every target is a film. Home's logo-only slides omit a text title; a collection detail request can supply that title. The current web slideshow defaults to an eight-second interval, but actual TV timing remains independently unverified.

Desktop/mobile background maps contain width-keyed filenames. Concatenate the supplied, validated `slideImagePath` and selected filename; title artwork is `slideImagePath + logoImage`. Current editorial assets live under `https://cc.criterion.com/uploads/storyBlocks/`; allow that exact origin and bounded path/filename data, reject path traversal and query/fragment injection. Do not construct editorial filenames from a title or reinterpret them as JW labels. Direct HEAD requests for Home's first desktop background and logo returned HTTP200 image/WebP, without downloading pixels. The public New slides additionally contain promotional `video`/`mobileVideo` fields; those URLs are excluded from catalog fixtures and were not fetched. Artwork metadata does not establish ownership for redistribution.

The admitted editorial paths are `storyBlocks/thumbnails/<filename>` and `storyBlocks/<numeric ID>/thumbnails/<filename>`. Basenames permit ASCII letters/digits, underscore, hyphen and the observed comma, with an exact `.webp` suffix. They admit no directory separators, query, fragment or encoded traversal. [The artwork module](artwork.md) owns fetching and decoded-memory admission.

Home's Popular Movies link targets `/categories/QGtQj94z/popular-now`; public `GET /api/media/QGtQj94z` returns a category titled Popular Now with a generic primary playlist, containing more items than the Home rail. New's Newly Added Films link targets `/discover/newly-added`; ordinary public `GET /discover/newly-added` returns the same HTML transport with one type-20 grid containing its supplied catalog items. Its captured `galleryWrap: 1` and absent continuation agree with the renderer. Admit supplied destinations through their measured transport; do not guess playlist endpoints from IDs.

## Public live metadata

Criterion 24/7's public `/api/media/1emmgvqX` record has `contentType: live`, duration zero, empty playlists and a `schedule` array. Schedule programs supply film type/title, duration seconds, optional catalog ID and UTC-second start/end timestamps. Empty observed IDs mean there is no catalog link; malformed nonempty IDs reject the response. Required `start_time`/`startTime` and `end_time`/`endTime` aliases must agree. The adapter admits calendar-valid canonical UTC values, positive ordered nonoverlapping intervals, gaps and at most 256 programs. This public schedule supersedes the absence of a schedule in older help copy. A schedule does not establish current trusted TV time, license entitlement or live playback; do not derive saved progress from the live record's zero duration.

These contracts supply real public editorial discovery to the independent client. They do not establish the Android TV app's transport, full composition, image selection, geometry, animations or subscriber state. Official-app observations remain separate from these web contracts; [product acceptance](product.md) and the account/playback boundaries below still apply.

## Web session and entitlement

The public client uses Auth0 and Cleeng. The current activation authority is [login.criterion.com/activate](https://login.criterion.com/activate): an anonymous GET returns Auth0 Universal Login with a POST code-entry form and hidden transaction state. The separate `www.criterionchannel.com/activate` redirects to `/app-update`; it does not establish the login host's availability. [Public issuer metadata](https://login.criterion.com/.well-known/openid-configuration) identifies `https://login.criterion.com/`, `/authorize`, `/oauth/token` and `/oauth/device/code`, with device-code, authorization-code and refresh grants plus S256 support. These are tenant capabilities, not admission of an independent client or proof of its API audience/scopes. The [FAQ](https://www.criterion.com/faq/channel) distinguishes linked Criterion accounts from paid Channel access.

An anonymous `GET /login?returnTo=/` returned HTTP307 to that issuer's `/authorize`, with `response_type=code`, `code_challenge_method=S256`, scopes `openid profile email offline_access` and `redirect_uri=https://www.criterionchannel.com/auth/callback`; no audience parameter was present. The server sets an opaque transaction cookie. No authorization redirect was followed, code submitted or subscriber session read. The configured `__session` and server storage describe a first-party web session; its cookie attributes and sharing with a packaged origin remain unverified. The [public-auth provenance](../tests/fixtures/provider/provenance.json) preserves response hashes and nonsecret metadata, excluding transaction/client values.

| Source-derived web route | Consumed contract |
| --- | --- |
| `GET /auth/profile` | HTTP 204 means no user; otherwise successful JSON supplies a user. Fields consumed include `sub`, `collaborator`, `cleeng_id`, `firstname`, `lastname`, `email` and `marketing_emails`. Full schema remains unknown. |
| `/login?returnTo=<path>` | Hosted navigation; signup adds `screen_hint=signup`. Logout navigates to `/logout` after local session invalidation. |
| `GET /api/auth/refresh-token` | Nonempty `token` string; optional `forced === true`. Forced refresh adds `force=1` and `x-forced-refresh: 1`. |
| `POST /api/auth/clear-session` | No body; used after expired/revoked sessions. |
| `GET /api/subscription/check-entitlement` | Access requires `accessGranted === true`; subscriber additionally excludes `grantType === "collaborator"`. |
| `POST /api/subscription/sso-login` | No body; consumes `responseData.jwt` and `responseData.refreshToken` for Cleeng. |
| `PUT /api/profile/update` | JSON `{ email, first_name, last_name, marketing_emails }`; success causes profile reread. |
| `POST /api/auth/logout-all-devices` | No body; client checks success status. No per-device list/remove contract was found. |

The [profile SDK](https://www.criterionchannel.com/_next/static/chunks/041rmhcvia7aq.js), [auth/entitlement client](https://www.criterionchannel.com/_next/static/chunks/1z1ya1oc-yyrn.js), [navigation](https://www.criterionchannel.com/_next/static/chunks/3yjgq_qr-o81n.js), [Cleeng handoff](https://www.criterionchannel.com/_next/static/chunks/3x9g_1b8uocho.js), [profile editor](https://www.criterionchannel.com/_next/static/chunks/2wyhltnt9y3o6.js) and [device logout client](https://www.criterionchannel.com/_next/static/chunks/3k3sjiru8d99i.js) establish these expectations. Only the unauthenticated login-start navigation was invoked; profile, token-refresh, entitlement and account operations were not.

The authenticated fetcher initially calls plain `fetch(relativeRoute, init)`, without adding Authorization or a credentials override; [Fetch defaults](https://fetch.spec.whatwg.org/#concept-request-credentials-mode) retain same-origin cookies. On HTTP401 with JSON `authExpired === true`, it fetches `/api/auth/refresh-token` the same way, then retries with `Authorization: Bearer <token>`, at most twice, while still retaining cookies. This proves bearer retry, not bearer-only acceptance or conversion of a device grant into the web session. A second retried expired response clears the local session. Refresh `error.code` values `missing_session`/`missing_refresh_token` clear the local session; `failed_to_refresh_token` with `error.cause_code=invalid_grant` means revoked. Other failures are transient. A user lacking both collaborator status and `cleeng_id` is held by an account-linking error. Real web response nullability, token lifetime and refresh persistence remain unknown. Do not infer the production middleware host from a compiled staging fallback.

The signed Android TV package establishes the current native public registration and [Auth0 Device Authorization](https://auth0.com/docs/get-started/authentication-and-authorization-flow/device-authorization-flow/call-your-api-using-the-device-authorization-flow) forms. [The session module](session.md) owns their fixed issuer/client/scope configuration, bounded polling, refresh and cancellation. Device acquisition sends client ID and scope without audience or client secret. Native tokens use a raw subscriber `x-auth-token` header, independently of the bootstrap capability carried as `Authorization: Bearer …`. Anonymous `https://mw.criterion.com/api/init` establishes the US/CA middleware origins. These source and anonymous-bootstrap observations do not prove independent account middleware admission or playback. [RFC8628](https://www.rfc-editor.org/rfc/rfc8628) requires the returned interval, pending/slow-down handling and terminal denial/expiry. Secure TV persistence and actual refresh admission remain required; a public native application cannot protect a shared client secret.

Auth0 refresh credentials, website refresh response tokens and Cleeng customer tokens have distinct owners. The website exposes `{ token, forced? }` for bearer retries; no direct Auth0 refresh exchange or `refresh_token` field is established by that client response. Native token lifetime/rotation, secure storage and serialized refresh must follow the actual admitted grant; [rotation](https://auth0.com/docs/secure/tokens/refresh-tokens/refresh-token-rotation) can revoke a family after reuse. Cleeng's [external-identity SSO](https://developers.cleeng.com/reference/sso-login) uses trusted middleware with a publisher credential; the observed public publisher ID is not that credential. The observed customer-token handoff matches [web widget methods](https://developers.cleeng.com/docs/cleeng-hosted-widgets-global-communication-methods), not a native-TV login contract. Generic [Cleeng PIN Pair](https://developers.cleeng.com/docs/device-login-flow-pin-pair) requires Cleeng as identity provider and does not establish Criterion's Auth0 flow.

## Native account and progress

The signed Android TV reference's configuration and caller chain selects the required public bootstrap US/CA base before appending its native routes. These are middleware routes, distinct from the website's same-origin paths. [The account adapter](account.md) owns the fixed implemented read/write methods, dual private header roles, native DTO admission and mutation uncertainty. Source tracing establishes route construction and request schema; it does not establish our subscriber's server acceptance. Native playback appends `/playback/<identifier>` with a `drm_policy` string; its webOS policy, production response, signed source/license configuration and independent origin remain unadmitted.

Native saved positions use signed Int64 seconds. The native writer divides player milliseconds by 1,000 with integer truncation; ended reports set both position and duration to the resulting duration seconds. The request builder rejects negative values, admits zero and has no observed upper clamp. Resume accepts a positive saved position with positive duration below completion, then multiplies position by 1,000 for player start. The same native completion cutoff is 95 percent below 300 seconds and 98 percent otherwise. [Native progress](progress.md) owns the deployed request MIME/nullable serialization, status-specific Unit conversion and optional Float32 catalog duration consumers. These source-derived units do not establish accepted server ranges.

The native periodic report owner runs while Playing, tracking is enabled and content is not live. Positive initial duration triggers an immediate report; otherwise it waits one second once before checking current state. Each subsequent ten-second delay begins after the awaited report, so request time adds to the period. One-shot completion reports require tracking, nonlive content and positive duration. Broader background/close flush ownership and server ordering remain unverified. The ordinary native continuation-delete caller forwards the UI media ID unchanged with `delete_series=0`; true series-removal semantics are unestablished.

This native contract comes from bounded public method/schema traces of the signed reference, with receipt hashes recorded in the primary journal. No installed account storage, protected response, provider mutation or license value was read for that audit. [Reference observations](reference-app.md) separately record official-client cross-device behavior. Implementing a report loop still requires an admitted player clock, issued-write lifetime and durable uncertainty ownership.

## Licensed playback boundary

The [player loader](https://www.criterionchannel.com/_next/static/chunks/3-c73_d_zowt2.js) obtains `GET /api/jw/player` as `{ url, exp? }`. On a subsequent loader call within 120 seconds of epoch-second expiry, it invalidates/reloads the script; no scheduled refresh timer is established. The [playback client](https://www.criterionchannel.com/_next/static/chunks/1n_n48e9_udja.js) fetches authenticated `GET /api/playback/<ID>`, with `safari=true` for Safari and a separate `drm_policy=cast` request for casting. It consumes `playlist[0].sources`, optional tracks/image/title, and hands them to JW Player. After auth retry, the client classifies HTTP 401/403 as entitlement failures, 404 as unavailable, and 429 with `x-playback-route-limit` as its first-party rate limit; actual causes remain unverified. It retries once on HTTP 408 or server status >=500, or requests again after missing sources; network exceptions without numeric status are not covered by that retry.

The official website decodes licensed subscriber playback, as recorded in [the reference observations](reference-app.md). Independent player bootstrap, signed URL lifetime, license policy/headers, codec/quality, permitted packaged origins and C4 entitlement remain unverified. JW's generic [DRM integration](https://docs.jwplayer.com/platform/docs/protection-studio-drm-jwx-web-player-integration) describes authenticated server signing and expiring source/license URLs; those examples do not establish Criterion's exact deployed policy. Publisher secrets never belong in the client, and DRM stays with the licensed platform implementation.

### Native TV request construction

Static method/schema traces of [the signed Android TV reference](reference-app.md#running-reference-and-identity) establish separate native regional requests. Media detail uses `GET <base>/content/media/<ID>` with the bootstrap Bearer capability. Playback uses `GET <base>/playback/<ID>?drm_policy=<policy>` with that capability and raw Auth0 access token in `x-auth-token`. Entitlement uses `GET <base>/subscription/check-entitlement?t=<currentTimeMillis>` with the same two headers. The selected base comes from the admitted bootstrap's US/CA map. These are native middleware routes, distinct from the website's `/api/jw/player` and `/api/playback` routes; static construction does not prove server acceptance or transport-added headers.

The Android policy selector sends lowercase `high` only when Widevine reports security level `L1`; other levels and exceptions select `medium`. Its Boolean `drm_downgraded` preference, default false, forces `medium` when true. The enum also contains other policies, but their presence does not establish accepted values, quality or offline rights. This Android selector cannot choose a webOS policy or establish DRM capability. Entitlement requires `accessGranted: Boolean` and `customerId: Int`; the native consumer caches the Boolean and also checks entitlement on a playback-failure path. Optional offer/grant/message strings, expiry and data do not establish grant policy or expiry units. A preflight before every playback request is not proved.

The native playback response requires a playlist and models optional expiry/cast fields. Its ordinary player mapping takes the first playlist item and first DASH source, with no HLS fallback on that path. DASH requires `file`; optional DRM supplies `widevine.url`. The player receives a DASH MediaItem, title from media detail and optional Widevine UUID/license URI. A `thumbnails` track supplies preview artwork; that mapper does not forward response tracks as external captions or audio configurations. The [pure account projection](account.md#playback-response-projection) implements the guarded source-derived response grammar independently of request execution; complete admitted DTO validation precedes its exact selection. Actual manifest tracks, license headers/body, signed-host policy, expiry/renewal and decoded playback remain unobserved. The exact input hashes and bounded method receipts belong in the primary journal and private evidence, rather than a redistributed APK or protected configuration.

### Stock webOS playback admission

LG's current [web engine specification](https://webostv.developer.lge.com/develop/specifications/web-api-and-web-engine) identifies webOS25 as Chromium120. Its [streaming/DRM specification](https://webostv.developer.lge.com/develop/specifications/streaming-protocol-drm) lists Widevine Modular17 and PlayReady4.4 through HTML5 MSE/EME, with hardware Widevine support; LG's simulator/emulator has no DRM support. [JWX compatibility](https://docs.jwplayer.com/platform/docs/protection-studio-drm-overview) includes webOS6+ with both DRM systems. This establishes a licensed stock-web playback surface to investigate, not a direct Rust CDM/decode API or successful Criterion playback. [JWX policy guidance](https://docs.jwplayer.com/platform/docs/protection-studio-drm-with-jw-platform-policy-reference) suggests different generic policies for LG and AndroidTV; it cannot identify Criterion's deployed policy or maximum quality.

The conditional interoperability path is an admitted subscriber grant/session, verified entitlement and provider-issued signed playback configuration handed to a stock MSE/EME player. Criterion's server remains responsible for signing; a client must never mint delivery/license signatures with publisher secrets. Native Rust and the web player need an authenticated, bounded control boundary and coordinated lifecycle before that architecture is admitted. Actual API bearer acceptance, supported client/origin, CORS, CDM policy, renewal, audio/caption tracks and C4 playback remain verification requirements. LG's [Keymanager3](https://webostv.developer.lge.com/develop/references/keymanager3) documents app-owned TEE crypto; the independent native caller's rights, supported modes and persistence on this TV must be verified before selecting it for refresh storage.

## Implementation boundary

The first Rust slice may consume the verified public catalog with TLS validation, bounded requests/cache, fixed origins, validated metadata and explicit network/error states.
