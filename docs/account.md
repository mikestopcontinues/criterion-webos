# Native Account Boundary

[criterion-account](../crates/criterion-account/src/lib.rs) owns native middleware bootstrap, anonymous Native Detail, private HTTP credential construction, bounded My List IDs/Watch List/Continue Watching and entitlement reads, and explicit list writes. Its pure playback-response decoder issues no request. [Subscriber Session](session.md) owns Device Authorization, refresh, logout and in-memory subscriber credentials. [The provider contract](provider-contract.md) owns source evidence, entitlement and licensed playback admission.

The composed host SDL/GLES application has admitted the production initial Watch List response and one native filtered group through its signed-in My List rail. The live grouped journey is partial: the filtered response had no observed next cursor, and the continuation test failed. Explicit cleanup logout received issuer acknowledgment, and the application disposed its private view, work and resources. Temporary activation captures were removed; no private list contents or credentials were retained, and no list, progress or playback mutation was made. This establishes the initial read, that one filtered group and host navigation/lifecycle. Other filters, actual continuation, list writes, other subscriber methods, live refresh/rotation, secure persistence, entitlement and C4 execution remain unadmitted.

Grouped My List, supplied Continue Watching and anonymous Native Detail compose through the shared account worker with independently reviewed synthetic CPU coverage. The actual host SDL/GLES My List journey paints its exact native Film detail and restores its selected shelf before logout; [application ownership](application.md) records those contracts. One production anonymous Film has passed the composed account worker, native Film display, Information and warm Back journey with real metadata and current public artwork. Its initial Collection and navigation origin are explicitly synthetic; this does not admit live native discovery, My List, every subtype or subscriber playback. Production Continue Watching, remaining account methods, entitlement and playback remain unadmitted.

`AccountClient::bootstrap` makes one anonymous request through the fixed HTTPS middleware transport. The public endpoint and exact US/CA API bases have one source owner in [the wire module](../crates/criterion-account/src/wire.rs). The response's country, token and base URL map are required; only the exact supported bases and US/CA country values are admitted. Host, scheme, credentials, port, path, query or fragment changes reject the response. No arbitrary URL or route is accepted. The opaque bootstrap token stays private and zeroizing; unneeded configuration fields are ignored. The response and base URL records require JSON objects; positional arrays are rejected.

One operation owns a client at a time; concurrent calls return `Busy` without a queue. A replacement bootstrap erases the previously admitted token and region before its request. Failure, cancellation or a dropped replacement cannot fall back to that old cache. Cancellation rejects late publication; disposal also erases the admitted cache and prevents further operations. The runtime owner controls UI publication and retires departed read generations. Issued writes have the separate lifetime below.

`credentials` explicitly borrows an unexpired subscriber token through `Session::with_access_token` to construct two validated, sensitive HTTP values. The bootstrap token supplies `Authorization: Bearer`; the subscriber access token supplies raw `x-auth-token`. Neither is a publisher credential, browser cookie or substitute for the other. Their getters are private-value capabilities for an admitted HTTP transport. Their `Debug` output is redacted.

Header buffers retain a zeroizing owner through the pinned [HTTP HeaderValue implementation](https://docs.rs/http/1.5.0/src/http/header/value.rs.html). Explicitly created headers remain owned by their callers until dropped. Later session or account disposal cannot erase a header that a caller already holds; the runtime must bound outbound jobs, reject stale publication and retire their headers with their generations. HTTP/TLS internals and URL/parser scratch may make temporary copies outside application-owned erasure. Nothing logs tokens, headers, bodies or authentication query values.

The [transport](../crates/criterion-account/src/transport.rs) verifies TLS with static roots and the pinned crypto provider, rejects proxies and redirects, disables automatic retries and body decoding, and accepts only bounded, nonempty JSON. Its total ten-second deadline includes body delivery, with a shorter connect deadline, one active request per instance, a capped response and typed diagnostics without external payloads. Bootstrap rejects all supplied credentials before contact and does not retain or send cookies. Test-only loopback constructors preserve certificate and hostname verification.

## Anonymous detail

`AccountClient::detail` issues a bodyless regional native media GET with bootstrap authorization and no subscriber capability. It does not borrow a Session, initiate activation or refresh credentials. The transport admits only the fixed media route and a validated media ID; the response must match that exact requested ID. [detail_wire.rs](../crates/criterion-account/src/detail_wire.rs) owns aggregate body, text, depth, playlist, season, item and retained-allocation limits, including discarded fields. Nine native subtypes retain bounded metadata and native child summaries rather than recursively exposing complete details. Optional nullable Episode series identity/title remains explicit. Custom ratings, playable paywall and license-expiry interpretation are outside this admission.

## Subscriber method admission

The signed native reference's caller/configuration chain closes its regional base to the bootstrap's required US/CA map. The bootstrap country selects the supported region. [The transport](../crates/criterion-account/src/transport.rs) owns fixed authenticated GET suffixes for `/content/my-stuff-ids`, `/content/watch-list`, `/content/continue-watching`, `/subscription/check-entitlement` and the playback route below. My List IDs and Continue Watching have no query. All require the distinct private headers; missing, incorrectly framed, oversized or nonsensitive credentials reject before contact. Credentials belong to individual requests and never become client defaults. Bootstrap remains credential-free. Website routes do not prove native middleware routes.

`watch_list` takes one explicit `WatchListRequest`. The transport always requests the native caller's observed `page_limit=50`, then appends an optional `content_type` and an optional `pagination_key` in that order. The closed GET filter is distinct from the nine-variant POST enum: All omits `content_type`; the other choices send `film_series`, `collection`, `original_franchise`, `supplement` or `category`. A returned cursor can be supplied unchanged for one continuation request. The maintained URL encoder percent-encodes the raw value once, with spaces normalized to `%20`; literal plus and percent become `%2B` and `%25`, and non-ASCII text uses uppercase UTF-8 escapes. No query body, sort, offset or page number is invented. The fixed 50 is a caller policy, not a proved server maximum. Verified TLS fixtures cover query construction and composed request lifecycle. The production host admission above covers the initial All request with `page_limit=50` and one native filtered group. It does not establish all filter choices or continuation: the observed filtered response supplied no next cursor. The composed application has synthetic coverage for grouped traversal, exact cursor issuance, first-key merging and session/history retirement; [application ownership](application.md) records that separate layer.

`my_list_ids`, `watch_list`, `continue_watching`, `entitlement` and `playback` reserve the client, snapshot the borrowed subscriber header, and check account generation/disposal after delivery. They compare the current unexpired Session token with the captured token while holding both owners through response admission. Rotation, logout, expiry and disposal reject old publication as `Stale`; the account owner never refreshes or retries a subscriber session. This token comparison is not a Session epoch API: the runtime must serialize lifecycle work and reject results from its departed account/UI generation, including reauthentication that returns identical token bytes. Cancelling or dropping an authenticated read retains an already admitted bootstrap; replacing bootstrap has the erasure behavior above.

The [native summary decoder](../crates/criterion-account/src/native_wire.rs) requires the SDK's `watchlist`/`positions` or `playlist`/`positions` fields for subscriber responses. It bounds each array to 512 entries, the whole summary response to 64 KiB, titles to 1,024 UTF-8 bytes and commentary labels to 128 bytes; text must be nonempty without control characters. Media and series IDs reuse the provider's validated eight-character ASCII alphanumeric type. These admission bounds are application policy, not claimed native SDK restrictions. Unknown fields are discarded, including media/source/license URLs. Debug output retains only coarse kinds/counts. Response records, nested positions and paging require objects through streaming Serde map admission; arrays remain valid only for the declared collection fields. [Anonymous Detail](#anonymous-detail) has its own aggregate decoder policy.

The native media projection differs from the public website decoder. Its nine `contentType` subtypes have required IDs/titles; playable subtype duration is optional nonnullable Float32, while container subtype duration is absent. A present null, negative or nonfinite duration rejects; omission stays absent. No integer conversion or zero default is invented. Native LocalDate strings are calendar-validated by pinned `time` with this application's four-digit ISO date bound. Positions preserve signed Int64 `pos`/`dur` and optional nullable commentary/series metadata; no `device_id` is inferred. The provider contract owns native position units, completion and reporting cadence; this decoder preserves signed fields without conversion. [Native progress](progress.md#native-catalog-duration) owns the proved subtype-specific duration consumers; server mutation settlement remains separate admission. The `watch_list` read also requires native `paging` and `type_counts`. Returned page limit and counts preserve their Int32 wire values without driving a request. The opaque nullable continuation reuses the provider cursor type, bounded to 512 UTF-8 bytes and rejecting empty strings and control characters. Empty-cursor rejection is application policy: the native SDK omits null but forwards an empty string. The count map permits at most 128 unique nonempty labels of 64 bytes; its labels do not define the request filter enum. Returning a cursor never fetches another page. This adapter implements no automatic pagination, row merging, deduplication or progress writes. Cursor lifetime, filter/region binding and server snapshot semantics remain unobserved.

The signed reference's nine concrete media variants return the same field serialized as required `mediaid` for their Watch List key. Its successful projection preserves that raw field through the row key, and its append handler keeps the first existing key before new items. This closes the client field mapping for the admitted variants; it does not establish cross-content-type server uniqueness, immutable identity or future subtype behavior. Application pagination must preserve that first-key order and keep group cursors separate rather than deriving keys from titles or list positions.

## Native Detail membership observation

[The application membership owner](../crates/criterion-app/src/application/list_membership.rs) issues one typed My List IDs read after an eligible signed-in native Detail is ready. [The controller scope](../crates/criterion-app/src/controller/list_membership.rs) binds it to the exact requested root, original kind, account epoch and never-reused foreground visit. A Series primary Episode remains a separate identity. Live is excluded. Credential waits and retiring work share the original demand deadline; ordinary polling does not retry a failed or expired observation.

The result reduces to current-root presence only. Unrelated IDs and every returned position are discarded rather than merged into the Continue Watching snapshot. Membership overlays a temporary borrowed view and never enters cached Presentation or navigation history. Navigation, background, logout, relinking and disposal retire the observation and join issued work before a successor. Signed-in cached Back and resumed foreground begin fresh observations; signed-out Back issues no IDs read.

Synthetic worker and actual Application tests cover request framing, identity, original deadlines, held-read retirement, cached Back, background, disposal and identical-token relinking. The actual host SDL/GLES journey admits first-party linking, one default initial Watch List read, one selected ordinary root anonymous Detail and one same-region My List IDs read. It verifies current known-presence painting, sixteen settled frames without another read, exact warm shelf Back and one issuer-acknowledged logout with joined disposal. The sole external activation capture is deleted after cleanup. This admits that bounded production journey; remaining roots/subtypes, known absence, relinking, foreground changes and C4 behavior still require their own live acceptance. Both UI input and the Application action consumer refuse signed-in list mutations; an observation does not admit the durable write owner below. Signed-out activation preserves the current origin without replaying a list write after linking.

## Entitlement projection

`AccountClient::entitlement` accepts the caller's exact signed Unix milliseconds and issues the fixed regional bodyless GET with `t=<captured_unix_time_ms>` and the two private header roles. It preserves required `accessGranted: Boolean` and `customerId: Int32`; missing, null, wrong-type and out-of-range fields reject. Customer identity is private and redacted in diagnostics. There is no inferred timestamp, expiry, refresh, retry or DRM policy. The response is provider data; its Boolean does not grant a media or license resource capability.

The [account worker](../crates/criterion-app/src/account.rs) dispatches typed entitlement reads through the existing joined, single-worker lifetime. Result ownership includes its checked generation, root Session epoch and exact captured timestamp. Synthetic tests verify regional requests, stale credentials, relinking, cancellation, background, disposal and exhaustion. The application has no entitlement demand/result consumer yet. Production entitlement, subscription-denial presentation and licensed Play remain unadmitted. The native reference checks entitlement on a playback-failure path; a preflight before every playback request is not established.

## Playback response projection

`AccountClient::playback` takes an explicit `NativePlaybackRequest` with the selected media ID and one closed native `DrmPolicy`. It issues one bodyless regional `GET /playback/<ID>?drm_policy=<value>` with the distinct bootstrap and current subscriber headers. The policy type preserves the signed reference's six values without a default or webOS capability chooser. The request identity remains separate from the returned media identity. The transport applies a 512 KiB playback-response bound while preserving the shared deadline, credential checks and current-read admission; it performs no entitlement preflight, refresh, retry or license request.

[The pure playback decoder](../crates/criterion-account/src/playback.rs) validates a supplied response and returns `Selected`, `EmptyPlaylist` or `NoDash`. Every admitted playlist/source DTO and thumbnail-track prefix is checked before selecting the first playlist item and its first exact DASH source. Later entries cannot supply a fallback. Missing or null thumbnail file on the first matching track stays absent; numeric primitive spelling is preserved. The source-derived duration normalization precedes subtype projection, using binary64 parsing and signed Int32 saturation/truncation before the guarded Float32 summary.

Selected DASH, optional Widevine-license and thumbnail candidates stay private and zeroizing, with borrowed access and redacted diagnostics. Empty and control-containing strings remain exact candidates; they are not validated URL, origin, license or viewing capabilities. The existing guarded media-ID/title/date/duration subset and explicit body, depth, aggregate-item, primitive and retained-allocation limits remain project admission policy. Unowned full metadata, general serializer coercion and nonempty optional OffsetDateTime grammar are outside this projection. Application-owned erasure does not guarantee parser or HTTP scratch erasure.

The decoder and authenticated read have synthetic boundary, numeric, currentness and verified TLS-fixture coverage with independent source review. [The account worker](../crates/criterion-app/src/account.rs) delivers the redacted typed selection under its checked generation and root epoch, matching the captured request ID and policy independently from the returned media ID. Joined predecessor retirement, deferred unsigned/background demand, same-token relinking and disposal have synthetic coverage. The application player producer/consumer remains unfinished. Production responses, a supported webOS policy, media/license hosts and headers, expiry/renewal, CDM and licensed playback remain unadmitted.

## List write ownership

`add_watch_list` and `remove_watch_list` use the exact native POST/DELETE routes and validated media identifiers. The add method takes an explicit `WatchListContentType` from the verified native request enum. The ordinary native Detail caller preserves its root ID and maps Film, Series, Collection, Episode, Supplement, Category, Franchise and Original to their corresponding request types. Its Live branch rejects before constructing that context; the enum's `live` value does not establish an ordinary Detail action. A Series primary Episode remains a separate playback identity. POST encodes only the required ID/type fields into bounded zeroizing storage, and DELETE has no body or query. The transport's `send` seam derives method/path/body from typed targets; the obsolete GET-only seam is removed. Target diagnostics inherit the media identifier's redaction.

Both methods return `Result<SyncReceipt, WriteFailure>`. A valid object response preserves the native optional nonnullable `sync` Boolean, including absent-field default false. The receipt is not an `Applied` result, and false is not invented as failure. The runtime rereads IDs to report observed membership. A matching GET does not prove an unknown earlier mutation settled.

`WriteStatus::Issued` means admitted work may reach the transport, not proof of server delivery. Before-admission failures return `NotIssued`; the transport reserves `Busy`/`InvalidRequest` for definite pre-contact refusal. All potentially delivered failures, malformed receipts and stale token/generation results return `Unconfirmed`. Cancellation, dropped issued futures, disposal and poison recovery retain the same uncertainty even without a returned error. Subsequent writes refuse with `ReconciliationRequired`; reads and rebootstrap remain available and cannot clear that marker. There is no automatic reset/replay/recovery API.

The runtime must keep an issued bounded write alive through completion/deadline across navigation and logout, record its intent before polling, and retain unresolved status across owner replacement or restart. It must serialize Session lifecycle changes, report membership observations separately, and establish provider-supported recovery before clearing unresolved issuance. The crate's marker is volatile and does not establish durable TV storage or server settlement.

Behavioral tests exercise bootstrap replacement, hostile origins/schema/token bounds, exact regional routes, dual header roles, native optional/fractional media, stale Session changes, redaction, concurrent/cancelled/disposed/dropped owners and controlled local TLS delivery. The explicit `public_bootstrap` example makes one anonymous request and prints only a coarse region/result. Local fixtures and anonymous bootstrap establish neither independent subscriber admission nor secure TV storage, entitlement, DRM or C4 playback.
