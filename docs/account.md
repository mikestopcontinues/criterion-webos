# Native Account Boundary

[criterion-account](../crates/criterion-account/src/lib.rs) owns the native middleware bootstrap, private HTTP credential construction and bounded My List IDs/Continue Watching reads. [Subscriber Session](session.md) owns Device Authorization, refresh, logout and in-memory subscriber credentials. [The provider contract](provider-contract.md) owns source evidence, entitlement and licensed playback admission. Implemented requests do not establish server acceptance or subscription entitlement.

`AccountClient::bootstrap` makes one anonymous request through the fixed HTTPS middleware transport. The public endpoint and exact US/CA API bases have one source owner in [the wire module](../crates/criterion-account/src/wire.rs). The response's country, token and base URL map are required; only the exact supported bases and US/CA country values are admitted. Host, scheme, credentials, port, path, query or fragment changes reject the response. No arbitrary URL or route is accepted. The opaque bootstrap token stays private and zeroizing; unneeded configuration fields are ignored.

One operation owns a client at a time; concurrent calls return `Busy` without a queue. A replacement bootstrap erases the previously admitted token and region before its request. Failure, cancellation or a dropped replacement cannot fall back to that old cache. Cancellation rejects late publication; disposal also erases the admitted cache and prevents further operations. The runtime owner controls UI publication and cancels or disposes departed generations.

`credentials` explicitly borrows an unexpired subscriber token through `Session::with_access_token` to construct two validated, sensitive HTTP values. The bootstrap token supplies `Authorization: Bearer`; the subscriber access token supplies raw `x-auth-token`. Neither is a publisher credential, browser cookie or substitute for the other. Their getters are private-value capabilities for an admitted HTTP transport. Their `Debug` output is redacted.

Header buffers retain a zeroizing owner through the pinned [HTTP HeaderValue implementation](https://docs.rs/http/1.5.0/src/http/header/value.rs.html). Explicitly created headers remain owned by their callers until dropped. Later session or account disposal cannot erase a header that a caller already holds; the runtime must bound outbound jobs, reject stale publication and retire their headers with their generations. HTTP/TLS internals and parser scratch may make temporary copies outside application-owned erasure. Nothing logs tokens, headers, bodies or authentication query values.

The [transport](../crates/criterion-account/src/transport.rs) verifies TLS with static roots and the pinned crypto provider, rejects proxies and redirects, disables automatic retries and body decoding, and accepts only bounded, nonempty JSON. Its total ten-second deadline includes body delivery, with a shorter connect deadline, one active request per instance, a capped response and typed diagnostics without external payloads. Bootstrap rejects all supplied credentials before contact and does not retain or send cookies. Test-only loopback constructors preserve certificate and hostname verification.

## Subscriber method admission

The signed native reference's caller/configuration chain closes its regional base to the bootstrap's required US/CA map. The bootstrap country selects the supported region. [The transport](../crates/criterion-account/src/transport.rs) owns two fixed authenticated GET suffixes: `/content/my-stuff-ids` and `/content/continue-watching`, without queries. Both require the distinct private headers; missing, incorrectly framed, oversized or nonsensitive credentials reject before contact. Credentials belong to individual requests and never become client defaults. Bootstrap remains credential-free. Website routes do not prove native middleware routes.

`my_list_ids` and `continue_watching` reserve the client, snapshot the borrowed subscriber header, and check account generation/disposal after delivery. They compare the current unexpired Session token with the captured token while holding both owners through response admission. Rotation, logout, expiry and disposal reject old publication as `Stale`; the account owner never refreshes or retries a subscriber session. This token comparison is not a Session epoch API: the runtime must serialize lifecycle work and reject results from its departed account/UI generation, including reauthentication that returns identical token bytes. Cancelling or dropping an authenticated read retains an already admitted bootstrap; replacing bootstrap has the erasure behavior above.

The [native decoder](../crates/criterion-account/src/native_wire.rs) requires the SDK's `watchlist`/`positions` or `playlist`/`positions` fields. It bounds each array to 512 entries, the whole response to 64 KiB, titles to 1,024 UTF-8 bytes and commentary labels to 128 bytes; text must be nonempty without control characters. Media and series IDs reuse the provider's validated eight-character ASCII alphanumeric type. These admission bounds are application policy, not claimed native SDK restrictions. Unknown fields are discarded, including media/source/license URLs. Debug output retains only coarse kinds/counts.

The native media projection differs from the public website decoder. Its nine `contentType` subtypes have required IDs/titles; playable subtype duration is optional nonnullable Float32, while container subtype duration is absent. A present null, negative or nonfinite duration rejects; omission stays absent. No integer conversion or zero default is invented. Native LocalDate strings are calendar-validated by pinned `time` with this application's four-digit ISO date bound. Positions preserve signed Int64 `pos`/`dur` and optional nullable commentary/series metadata; no `device_id` is inferred. Duration/position units, progress cadence/ranges and mutation settlement remain unverified. Full paginated My List, list changes and progress writes are not implemented in this increment.

Behavioral tests exercise bootstrap replacement, hostile origins/schema/token bounds, exact regional routes, dual header roles, native optional/fractional media, stale Session changes, redaction, concurrent/cancelled/disposed/dropped owners and controlled local TLS delivery. The explicit `public_bootstrap` example makes one anonymous request and prints only a coarse region/result. Local fixtures and anonymous bootstrap establish neither independent subscriber admission nor secure TV storage, entitlement, DRM or C4 playback.
