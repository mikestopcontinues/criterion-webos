# Native interface

`criterion-ui` owns a pure remote navigation model, bounded egui scene painting and a main-thread GLES painter. The application supplies provider-admitted metadata and decoded public artwork, executes typed commands, and rejects stale asynchronous publication before updating the UI. Platform, account, provider and playback operations remain outside this crate.

## Application seam

`AppUi::handle(Action, &ViewData)` transforms one remote action and returns `Command` values. Card activation resolves current coordinates to `Target::Media(MediaId)` for public catalog IDs, `Target::Content(ContentTarget)` for validated discovery navigation or `Target::Native(MediaId)` for native account provenance. Both `CardAction::Open` and admitted native Episode `CardAction::Play` yield `ActivateCard` with the painted focus address and target. The controller validates that exact current card before choosing navigation or the selected-ID playback command; equal IDs in separate rows cannot exchange actions. Discovery preserves actual provider targets; no slug or media ID is synthesized. Playback and list commands still require a real media ID, exposed through `Target::media_id`.

Navigation history retains focus, scroll, detail modal state, Search query/group and the bounded filter draft/committed state. Fresh detail targets and fresh All Films entry close departed modals; Back restores the saved modal and selection. Preedit, select-all and pointer gestures are transient and are cleared on departure or restoration. The runtime must mirror an exact display/target stack for every Open, Login entry and Search or My List entry/exit, including navigation between two Discovery targets with the same Page. Restore(Page) selects that stored display rather than reconstructing content from the Page alone. UI activation ends the input batch even when the new target has the same Page.

Filter draft changes are separate from committed selections. `filter_selection` exposes the current committed selection for runtime consistency checks. Restore reissues the saved browse request and its admitted options; UI restoration emits no ApplyFilters command. The application maps filter indices to the admitted provider options. `ViewData` borrows the current hero, ordered rails, grid, optional detail and filter menu; Discovery uses hero/rails and My List uses the grid. The runtime projects discovery into precomputed typed display records and structured gaps, retaining an optional public live schedule without duplicating the whole DiscoveryPage. The current one-hero/rails projection does not establish richer slideshow/banner parity. ViewData borrows linking and account status through LoginView; the session owner retains the private linking values. MyListView lends typed group choices and checked optional counts without exposing account credentials or request cursors.

All Films keeps the four-column grid continuous through a bounded window. `CatalogWindow` supplies its global first position and separate tail state; cursors remain private to the controller. Moving near the tail stages continuation, and Down at an unloaded boundary keeps the current focus until the requested position is admitted and the input intent still matches. Loading and retry controls leave committed cards available. Up across an evicted head requests its earlier position; a header-to-first-card request likewise waits before focusing absent data. Paging adds no navigation snapshots. Card activation and rail departure record their exact global anchor before the navigation command, so Back retains the saved card and scroll even after the window has been trimmed. Visible painting and pointer/artwork lookup use the same global positions.

`AppUi::render(RawInput, &ViewData)` returns an egui `FullOutput`, visible card rectangles, public artwork keys, typed input commands and a `wants_text_input` signal. The scene uses a logical 1920×1080 canvas. [The reference application](reference-app.md) owns observed behavior and evidence; [view.rs](../crates/criterion-ui/src/view.rs) owns content layout values; the shared rail descriptor owns fixed navigation placement. CPU geometry checks cover the observed four-column landscape All Films grid. The current core includes Home, New, the grid, filter draft/Apply/Reset, detail actions, supplement tabs and an information modal. Search owns the six-column virtual keyboard, live lowercase queries, result groups/counts and three landscape result columns. Search detail Back retains query, group and card; returning from Search restores the prior Home focus and scroll. CPU painting does not establish complete official-app parity.

Media identity and artwork identity are distinct. A card has a typed activation target and an optional artwork key; the hero independently accepts background and title-logo keys, preserving logo aspect ratio. Hero action semantics explicitly distinguish opening media from playing it, independently of its display label. `admit_image` accepts bounded decoded pixels after the runtime validates origin, decode limits and publication generation. Admission queues no upload. A frame uploads only surviving cache entries, so bursts cannot retain evicted images in egui's pending texture delta. The caller consumes each frame's texture delta before producing the next frame. `has_image` reports admitted cache presence for both decoded and uploaded entries so the runtime does not repeat visible artwork requests. `image_bytes` reads the entry's exact admitted RGBA charge for pending or uploaded artwork without changing recency. `discard_image` removes one entry and queues uploaded texture release; ordinary bounded offscreen cache entries remain available for quick return. Cache and admission bounds are enforced in [images.rs](../crates/criterion-ui/src/images.rs).

Visible cards alone are painted; offscreen rails are skipped. Unavailable duration metadata is omitted instead of displayed as zero. Labels and buttons bound their display text before shaping, and synopsis pages bound both characters and rows. Information pages present bounded synopsis chunks and show a page count with remote arrows when more text remains. Typography and overflow require rendered reference comparison. Metadata labels elide to their visible line. Rail, search keyboard and modal control symbols use bounded typed geometry in [icons.rs](../crates/criterion-ui/src/icons.rs), independently of text glyph coverage. CPU checks cover icon shape bounds and unchanged remote focus/actions; native appearance requires framebuffer verification. The default egui fonts do not establish complete CJK or other international glyph coverage; typography and image crop parity require rendered reference comparison.

Native Detail borrows selected playlists, primary playback identity and bounded season choices from its presentation owner. Remote and pointer season selection update the same canonical local index. Displayed season counts reflect admitted Episode cards rather than the native server's Int32 count. Tab navigation keeps the selected header and active cards visible; dormant rails cannot receive card activation. The detail header omits an absent cast label, while Information headings follow admitted metadata presence. Header and Information paint independently prepared metadata lines under the [native duration contract](progress.md#root-detail-runtime-display). Cards borrow optional final runtime labels under their [separate formatting rules](progress.md#native-card-runtime-display). A supplied Featured block keeps its optional heading and cards outside the ordinary tabs. Its independent focus address, artwork, captions and saved fractions follow the same current-card ownership; an empty titled block still keeps tab entry within the viewport. CPU interaction and shape checks cover this composition. The synthetic host SDL/GLES journey additionally checks its current heading, runtime, focus, decoded-image and progress pixels through exact Featured Film Open, warm Back and logout. Standalone Episode parent interpretation, provider delivery, C4 appearance and reference-app label/geometry parity remain separate requirements. The [native Play action](application.md#native-play-action) owns current-root Series context and unavailable feedback; the UI paints its fixed notice while retaining Ready detail actions.

Eligible selected first tabs open the local sort sheet described by [application ownership](application.md). Remote and pointer input share its four choices, direction toggle, Apply and Close controls. The sheet takes input before the underlying Detail; opening or closing it cancels pending pointer activation. Dismissal restores the first-tab focus and its visible scroll position. Shape and actual input tests verify complete labels, modal bounds, focus and stale-press retirement. Direction arrows use the existing typed geometry and change to white on a gold focused row, together with their pending marker. Synthetic host SDL/GLES checks cover both directions, draft/apply/default, warm Back and logout; reference-app and C4 appearance remain separate.

## Input ownership

Remote navigation uses the six `Action` values. Pointer and text arrive only through `RawInput`, avoiding duplicate keyboard actions. Pointer release activates the currently admitted target only when its typed activation identity still matches the press. Leaving the viewport, losing focus, a remote action or replacement content cancels pending activation. Pointer presses preserve the painted window until release; hover does not move remote focus. Whole-card hit ownership includes visible metadata and uses the same content clipping as painting.

Events are consumed in their original order. Search accepts native Text, Paste and IME Commit while its field or virtual keyboard owns text input; preedit is transient. Editing appends at the end, with Backspace, native select-all replacement and IME deletion before the caret. Query admission bounds UTF-8 bytes after lowercase expansion to the provider's accepted size; empty/whitespace commands tell the application to clear results without requesting the provider. The application supplies group counts, binds the selected group to the admitted results and owns asynchronous request generations. Voice selection yields a typed runtime command; a working speech adapter is not established by this UI.

## Account presentation

`LoginView` borrows the session owner's activation code and complete verification URI. Its public variants distinguish signed out, requesting, awaiting activation, signed in, signing out, expired, declined and unavailable states; private values have no Debug implementation. The runtime supplies a never-reused challenge generation and remaining time, owns expiry, polling, cancellation and stale publication, and admits only the validated session instructions described in [session.md](session.md).

`begin_authentication` captures the current page, focus and scroll and yields Authenticate for deferred signed-out playback. Rail Log In also yields Authenticate; the signed-in Account rail opens the screen without starting another activation. Pending activation exposes Cancel; expiry and failure expose RetryAuthentication. Cancel or Back returns CancelAuthentication followed by Restore of the saved page. Leaving a pending link through the rail cancels linking too. Signed-in Back preserves the session; Logout is explicit, and leaving SigningOut never cancels an issued logout. Root must mirror the saved display history and retain the deferred playback target independently.

The signed-in rail exposes My List independently of Home discovery content. Its observed Search, Home, New, My List, All Films and Account ordering is shared by remote navigation, painting and pointer hit ownership through [rail.rs](../crates/criterion-ui/src/rail.rs); signed-out and pending states omit My List. Entering or leaving My List retains the same bounded display history as Search, and Left from its grid selects its own rail entry. Session departure retires My List history in both UI and runtime, preserving public origins and preventing Back or Cancel from restarting authorization for an inaccessible shelf. It also normalizes hidden My List focus to Log In and cancels the pending pointer press, preventing release from activating All Films after the rail shifts. The application executes the read-only AccountShelf entry and typed group/paging commands; optional public navigation cards remain provider supplied. The [group controls](../crates/criterion-ui/src/my_list.rs) retain six bounded per-group positions, including warm rail entry and Detail/Back. The published group is authoritative: pending changes block old card and Retry activation, while a newer choice can replace the pending intent. Signed-out admission scrubs private positions from every retained public snapshot and retires inaccessible group/retry focus. The English group labels and header geometry are project choices; numeric counts are omitted whole when the exact number does not fit. Shared global CatalogWindow commands preserve committed cards during loading/failure and allow explicit Retry. CPU behavior and geometry are covered. Actual host SDL/GLES synthetic frames verify the six visible header slots, selected group, focused continued grid, visible tail Retry and private-frame retirement after logout; [application.md](application.md) owns this journey. The initial production read and one filtered group are recorded in [account.md](account.md). Remaining filters, actual continuation, native-reference visual parity and C4 appearance remain separate acceptance.

Native Detail borrows read-only membership from the current application visit. Its list control distinguishes signed out, checking, known presence, known absence and unavailable observations; known presence paints the check mark. Both remote and pointer activation refuse signed-in writes. Signed-out activation preserves its origin without replaying a mutation after linking. [The account owner](account.md#native-detail-membership-observation) defines read and retirement semantics; durable writes remain a separate requirement.

Continue Watching cards paint the supplied saved fraction and preserve native activation provenance. Fractions do not trigger progress writes or infer a player clock. Session departure removes private rows from retained public history and unpainted output; [application ownership](application.md) describes the synthetic glyph-erasure and same-token lifecycle checks.

The activation screen presents the code, fixed activation website, runtime countdown and a vector QR encoded by [qrcode 0.14.1](https://docs.rs/qrcode/0.14.1/qrcode/struct.QrCode.html). The four-module quiet zone surrounds a bounded standard symbol. One mesh is cached per challenge and removed on state change or departure; there is no private artwork download, texture cache key, URL copy in navigation state or diagnostic output. Rendered galleys, meshes and frame output necessarily contain private instructions; callers must treat those frames and captures as private. This does not establish zeroization of egui's internal text caches. Account placement is couch-readable on the logical canvas but unmeasured against the official TV screen; actual phone scanning, GLES appearance and activation require native acceptance.

## GLES lifetime

`GlowRenderer::new` reads the current context's actual `GL_VERSION`. GLES 2 additionally requires `GL_OES_element_index_uint`, because the pinned maintained painter uses unsigned 32-bit mesh indices. ES 100 shaders are selected explicitly. [The vendored painter notice](../crates/criterion-ui/vendor/egui_glow/NOTICE.md) describes narrow cleanup fixes and upstream provenance; the crate brings no window system or bundled SDL.

The caller keeps the context current on the calling thread and disposes the painter before dropping the platform window. `paint(drawable_size, context, &mut output)` validates the surface and painter before consuming shapes or texture deltas, preserving a frame on admission errors. Rendering uniformly fits the logical canvas to the drawable size with centered black letterboxing, matching the platform's inverse pointer transform. Painter destruction is idempotent and releases shaders/programs, buffers, textures and any allocated VAO; failed initialization releases already-created objects.

Pure navigation and host egui frame tests establish CPU behavior and geometry only. Actual GLES initialization, extension availability, resource lifetime, color, artwork, resizing and performance require the application's serialized native checks. The TV and physical remote remain separate verification boundaries described in [development.md](development.md).
