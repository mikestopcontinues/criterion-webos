# Native interface

`criterion-ui` owns a pure remote navigation model, bounded egui scene painting and a main-thread GLES painter. The application supplies provider-admitted metadata and decoded public artwork, executes typed commands, and rejects stale asynchronous publication before updating the UI. Platform, account, provider and playback operations remain outside this crate.

## Application seam

`AppUi::handle(Action, &ViewData)` transforms one remote action and returns `Command` values. Card activation resolves current coordinates to `Target::Media(MediaId)` for known catalog IDs or `Target::Content(ContentTarget)` for validated discovery navigation before yielding `Command::Open`. Discovery preserves actual provider targets; no slug or media ID is synthesized. Playback and list commands still require a real media ID, exposed through `Target::media_id`. 

Navigation and detail history retain focus and scroll. The runtime must mirror an exact display/target stack for every Open and Search entry/exit, including navigation between two Discovery targets with the same Page. Restore(Page) selects that stored display rather than reconstructing content from the Page alone. UI activation ends the input batch even when the new target has the same Page. 

Filter draft changes are separate from committed selections. The application maps filter indices to the admitted provider options. `ViewData` borrows the current hero, ordered rails, grid, optional detail and filter menu; Discovery uses hero/rails and My List uses the grid. The runtime must retain raw Discovery block metadata; the current one-hero/rails projection does not establish richer slideshow/banner parity. ViewData does not own account data or URLs.

`AppUi::render(RawInput, &ViewData)` returns an egui `FullOutput`, visible card rectangles, public artwork keys, typed input commands and a `wants_text_input` signal. The scene uses a logical 1920×1080 canvas. [The reference application](reference-app.md) owns observed behavior and evidence; [view.rs](../crates/criterion-ui/src/view.rs) owns layout values. CPU geometry checks cover the observed four-column landscape All Films grid. The current core includes Home, New, the grid, filter draft/Apply/Reset, detail actions, supplement tabs and an information modal. Search owns the six-column virtual keyboard, live lowercase queries, result groups/counts and three landscape result columns. Search detail Back retains query, group and card; returning from Search restores the prior Home focus and scroll. CPU painting does not establish complete official-app parity.

Media identity and artwork identity are distinct. A card has a typed activation target and an optional artwork key; the hero independently accepts background and title-logo keys, preserving logo aspect ratio. Hero action semantics explicitly distinguish opening media from playing it, independently of its display label. `admit_image` accepts bounded decoded pixels after the runtime validates origin, decode limits and publication generation. Admission queues no upload. A frame uploads only surviving cache entries, so bursts cannot retain evicted images in egui's pending texture delta. The caller consumes each frame's texture delta before producing the next frame. Cache and admission bounds are enforced in [images.rs](../crates/criterion-ui/src/images.rs).

Visible cards alone are painted; offscreen rails are skipped. Labels and buttons bound their display text before shaping, and synopsis pages bound both characters and rows. Information pages present bounded synopsis chunks; typography and overflow require rendered reference comparison. Metadata labels elide to their visible line. The default egui fonts do not establish complete CJK or other international glyph coverage; typography and image crop parity require rendered reference comparison.

## Input ownership

Remote navigation uses the six `Action` values. Pointer and text arrive only through `RawInput`, avoiding duplicate keyboard actions. Pointer release activates the currently admitted target only when its typed activation identity still matches the press. Leaving the viewport, losing focus, a remote action or replacement content cancels pending activation. Pointer presses preserve the painted window until release; hover does not move remote focus. Whole-card hit ownership includes visible metadata and uses the same content clipping as painting.

Events are consumed in their original order. Search accepts native Text, Paste and IME Commit while its field or virtual keyboard owns text input; preedit is transient. Editing appends at the end, with Backspace, native select-all replacement and IME deletion before the caret. Query admission bounds UTF-8 bytes after lowercase expansion to the provider's accepted size; empty/whitespace commands tell the application to clear results without requesting the provider. The application supplies group counts, binds the selected group to the admitted results and owns asynchronous request generations. Voice selection yields a typed runtime command; a working speech adapter is not established by this UI.

## GLES lifetime

`GlowRenderer::new` reads the current context's actual `GL_VERSION`. GLES 2 additionally requires `GL_OES_element_index_uint`, because the pinned maintained painter uses unsigned 32-bit mesh indices. ES 100 shaders are selected explicitly. [The vendored painter notice](../crates/criterion-ui/vendor/egui_glow/NOTICE.md) describes narrow cleanup fixes and upstream provenance; the crate brings no window system or bundled SDL.

The caller keeps the context current on the calling thread and disposes the painter before dropping the platform window. `paint(drawable_size, context, &mut output)` validates the surface and painter before consuming shapes or texture deltas, preserving a frame on admission errors. Rendering uniformly fits the logical canvas to the drawable size with centered black letterboxing, matching the platform's inverse pointer transform. Painter destruction is idempotent and releases shaders/programs, buffers, textures and any allocated VAO; failed initialization releases already-created objects.

Pure navigation and host egui frame tests establish CPU behavior and geometry only. Actual GLES initialization, extension availability, resource lifetime, color, artwork, resizing and performance require the application's serialized native checks. The TV and physical remote remain separate verification boundaries described in [development.md](development.md).
