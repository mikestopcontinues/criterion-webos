# Application presentation

`criterion-app` separates loaded display data from asynchronous publication, native input and graphics. [The presentation module](../crates/criterion-app/src/presentation.rs) consumes provider-admitted discovery, catalog, Search and detail records. The controller owns requests, cancellation, navigation history and stale-result rejection; a projection does not fetch data or infer subscriber access.

The projection prepares display strings and artwork identities when data is loaded. `with_view` lends a `ViewData` for one callback, constructing temporary arrays of borrowed cards, rails and filter labels. It does not join metadata or clone display strings on each frame. Search retains each projected card once and changes the selected index set when the result group changes. Detail metadata is joined once, and playlist rows preserve the supplied order. Filter labels remain owned after the provider options leave scope; the controller must separately retain their typed values for applying selections.

## Native runtime

[main.rs](../crates/criterion-app/src/main.rs) owns the main-thread SDL window and GLES renderer. [Application](../crates/criterion-app/src/application.rs) composes the interface, input adapter, catalog controller, authentication, native My List reads and artwork owners. CPU frames settle earlier pointer and IME events before a later editing key or text commit; texture deltas remain owned until an actual foreground paint. Background retires public and account reads and artwork admission, while bounded authentication work retains its owner. Every error after application admission joins retiring account reads before issued logout/refresh settlement, text-input cleanup, worker shutdown and renderer disposal.

[Controller](../crates/criterion-app/src/controller.rs) mirrors the interface's navigation snapshots, retaining at most sixteen entries under an eight-MiB display/source estimate. A single process-owned browse-options value preserves filter index identity and is charged once; admission immediately reconciles retained history. Evicted views keep their typed query for reload. Fresh Search rail entry reissues the visible retained query and group without adding a second snapshot.

[All Films traversal](../crates/criterion-app/src/controller/catalog.rs) retains one base filter/sort request, a bounded display window and bounded observed input-cursor checkpoints. Continuation appends in provider order without adding navigation history; separate tail loading/error/retry preserves the committed grid. Back retains the exact window and global anchor, including interrupted appends. If the history budget evicts its display, the owner reloads the saved anchor's observed input-cursor page and verifies its media identity before publication. Filter Apply starts a fresh query and retires prior work; canceling a filter draft leaves the live query intact.

Only forward opaque pagination is admitted. An earlier position outside the checkpoint cache requires sequential traversal from the original first request, following each actual next cursor. Intermediate pages are discarded; one pending checkpoint and the operation deadline bound ownership. Navigation, background and departed focus retire reads. A traversal failure preserves the committed window and retries from its last known input cursor on explicit action; no query or focus reset is inferred. Empty pages with continuation, unavailable backward positions, repeated cursors and changed saved-anchor identity fail visibly. The end is an absent next cursor rather than the reported total. The [public web reference](reference-app.md) uses continuation and separate loading states; Android TV end-of-grid behavior and catalog stability across separate requests remain unverified.

Search trims and bounds the latest query before retaining it, then waits 250 ms on the injected monotonic clock. Changing the query immediately retires the old read; an empty query clears the display without a request. Same-query group changes keep a pending deadline or issued read and select the latest group on admission. With a Ready or Empty admitted display, every group uses the same retained projection, including empty groups, with the provider's original counts. A failed display remains failed until an explicit query or group action stages a fresh delay. Background, navigation and Restore cancel departed deadlines and reads. Interrupted Search history retains the typed query and group for a fresh delay; admitted history restores its exact projection without another request. [The controlled-clock journeys](../crates/criterion-app/src/controller/search_tests.rs) exercise these boundaries through the real catalog adapter with synthetic transports.

[Authentication](../crates/criterion-app/src/authentication.rs) borrows private linking instructions from the session and publishes request, awaiting, denial, expiry and signed-in states. Its one issued refresh settles before explicit logout can revoke the rotated credential. Failed or unknown rotation/revocation remains unconfirmed through relinking, later successful revocations and final cleanup; an unknown issued request is never replayed. Unsigned My List, Play and list actions enter activation while preserving their public origin. [The session owner](session.md) records live host linking/logout admission; [the account boundary](account.md) records the initial production My List read through the composed SDL/GLES application. Synthetic transports additionally cover the real owners' error, cancellation and history behavior. Mutations, secure persistence, licensed playback and the C4 must separately admit their flows.

[Accounts](../crates/criterion-app/src/account.rs) executes Watch List, Continue Watching and anonymous Native Detail through one worker and bootstrap owner. Each result is bound to its typed request, checked read generation and root epoch; issued retiring reads are joined before replacements proceed. Only subscriber requests borrow Session credentials. The application advances a checked root epoch before authentication intent, cancellation, logout or credential invalidation; credential bytes never identify that epoch. Exhaustion permanently disposes the owner instead of inventing another epoch. Departure, background and epoch changes prevent obsolete issuance or publication. Session departure retires My List history and private Continue Watching rows from current and retained public displays while preserving public origins and admitted anonymous metadata. Credential renewal retains the current subscriber demand deadline. This owner cannot settle or replay mutations. [Private traversal](../crates/criterion-app/src/my_list.rs) separately owns grouped windows and observed cursor checkpoints.

The [My List controller](../crates/criterion-app/src/controller/my_list.rs) executes the pure traversal state through Accounts. Each native filter retains its own admitted first-key order, saved demand, bounded card window and observed input cursors. Empty or duplicate-only pages can advance an observed continuation, while resource limits, cursor cycles and changed replay values refuse atomically with the committed cards retained. Provider counts select available groups; they never establish loaded rows or the end. The UI receives the selected native group, checked optional display counts and the same global window/tail model as All Films.

One monotonic demand deadline bounds automatic successors and credential replacement. Explicit Retry, resumed foreground work and navigation restoration begin a new bounded intent. Group changes or departed focus retire obsolete reads, including when the new selection already has a warm window. Background retains only resumable private traversal. Fresh My List rail entry reuses the newest same-epoch private group and card window without an unnecessary All read, while older Back snapshots preserve their own origins. Warm Back restores its selected group and card window. History eviction releases both display and source card allocations while retaining bounded checkpoints for the saved anchor. The root session epoch owns current and historical private data; logout or failed refresh erases it before another subscriber can reuse navigation. Routine focus demands update traversal intent without rebuilding committed display strings or artwork bindings. These controller and composed application behaviors have synthetic CPU coverage. [Artwork](../crates/criterion-app/src/artwork.rs) receives the current frame's visible keys and the current projection's immutable source bindings before polling. At most two tasks include their retiring handles. Visible records are bounded, and a visibility-prioritized twenty-four-MiB working set uses exact cached/decoded byte charges and reserves four MiB for an unknown card or eight MiB for an unknown backdrop. ## Identity and artwork

Catalog, Search and public detail cards use the admitted `MediaId` directly. Discovery cards and navigation items retain their exact `ContentTarget`, including nonmedia Discover and reserved routes. Native account cards retain `Target::Native` provenance independently of `Target::Media`, even when IDs are equal; activation uses that source's admitted meaning. Native Episode cards in Detail emit exact selected-ID Play commands without opening a replacement detail. The projection never constructs a slug from a title, adds an invented media identifier or manufactures a hero from a film row. [The native interface](interface.md) owns activation and painting behavior.

Artwork bindings pair a bounded opaque key with either an exact media identifier and image label or a validated editorial image. Keys are SHA-256 values over a versioned, type-tagged source identity including the image role. Labels and editorial URLs remain distinguishable even when a media target repeats; identical sources share one binding. The renderer receives only the key. The artwork owner validates and loads the binding's source, then owns decoded-pixel admission and stale publication.

Desktop editorial selection uses the supplied width candidates for the logical canvas: the smallest adequate width, or the largest available desktop candidate. It does not substitute a mobile source, a different image family or fabricated artwork. A logo-only slide keeps its text title empty and retains the supplied logo. Discovery hero activation opens its typed target; a display label does not establish a playable asset or entitlement.

## Represented data and current gaps

Discovery preserves the interleaved order of media rails and navigation rows. The current UI accepts one hero and ordered rails. The projection selects only the first slide of the first slideshow and reports additional slides, banners, row CTAs, gallery presentation settings, unsupported account-fed rows and unsupported new-window targets through structured gap counts. Explicit Continue Watching slots have the separate hydration contract above. Unrepresented artwork is not loaded. Missing hero target, CTA or desktop artwork remains explicit; it does not produce a replacement hero. Account-fed rows do not establish account synchronization.

Search group counts come from the provider's admitted counts. All includes every returned kind; Films, Collections and Supplements select their exact kinds while preserving order. The displayed total is the selected group's provider count rather than the number of returned cards. An empty selected group yields the empty state.

Public website Detail uses supplied media identity and playlist items without inventing routes. Collection, category and series metadata use the collection interaction surface; a supplement retains its supplemental surface. Public Live uses the existing play surface while retaining its typed schedule separately, with a count recording unrepresented schedule rows. A missing schedule media identifier stays absent. UTC timestamps do not establish the currently airing program, local timezone, progress or licensed playback. Absent runtime remains explicit for the renderer to omit.

[Native Detail](../crates/criterion-app/src/presentation/native_detail.rs) projects admitted metadata independently. Generic tabs retain supplied order; Series exposes the first Seasons group before Generic tabs, with local season selection and exact Episode actions. Current account progress can select its primary child and initial season through the independent rules in [native progress](progress.md#series-resume-selection). Only the active group owns card activation. The primary Series target refuses an equal root ID. Retiring a season restores visible card focus, or its season selector when empty. Header and Information borrow independent final runtime metadata lines under the [native duration contract](progress.md#root-detail-runtime-display). Detail children, My List and Continue Watching borrow separately prepared [card runtime labels](progress.md#native-card-runtime-display). Featured rows, sortable-tab behavior and optional Episode player-parent context remain unrepresented.

Information preserves metadata presence: absent or empty lists omit their heading, while a nonempty list joined to an empty string retains it. Content Warnings preserves its admitted optional value, including a native present-empty value. The public adapter retains its own upstream empty-warning policy. Four populated fields fit without overlapping descenders; calendar years on native cards use the plain year string. Display strings and their allocations remain owned and charged by the projection.

My List and Continue Watching Episode navigation preserves the saved key while requiring admitted parent Series context; missing-parent Episode and native Live actions refuse without a website fallback. Continue Watching autoplay remains retained intent rather than executed autoplay or resume. Signed-in Play and list commands still terminate at the unfinished application action boundary; metadata and explicit Play IDs do not establish entitlement or licensed delivery.

## Memory and verification

`estimated_bytes` supports the controller's navigation-cache eviction policy. It sums retained container capacities, owned display-string capacities and the exposed lengths of opaque provider strings. Private provider allocation capacity, allocator overhead and temporary callback arrays are outside this estimate, so it is not a measurement or ceiling for process RSS.

Fixture-backed CPU tests exercise the projection, runtime input ordering, authentication timing/uncertainty, history identity and artwork scheduling. The serialized SDL/GLES E2E injects actual SDL events, checks the resulting Search state, paints and reads the real host framebuffer and presents it. The production anonymous SDL/GLES journey additionally traverses five All Films pages inside the bounded window, opens the exact selected film, restores its warm Detail/Back state and returns to an evicted earlier page with its observed identity and order. Fresh frames verify current focused artwork; other visible images can still be placeholders. This establishes live public paging and restoration on the host. Recorded-cursor unit oracles remain separate from that live identity check; cold traversal after checkpoint eviction and controlled live tail retry are not established by this journey. Host rendering does not establish C4 rendering, reference-app visual parity, physical remote behavior or licensed playback. [The reference observations](reference-app.md) and [development procedures](development.md) own those separate acceptance checks.
